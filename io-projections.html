KV Cache Offload Storage IO

The memory envelope says how big the KV cache is. This page says what moving it to storage costs. The unit of measurement is LMCache's 256-token offload block — a sequence's cost is a linear multiple of it, so pick a sequence length and every cost below scales exactly.

IO size vs model release date, coloured by attention architecture. Block size does not track the calendar — it tracks the architecture: families that adopted MLA shrank three to fourfold, while GQA families grow with model size. Lines join each vendor's releases so a family's direction is visible on its own.

The same data split by architecture, so each family can be read on its own. Within a panel the colour is the vendor and the line joins that vendor's releases in order. Same axes in every panel, so they can be compared directly. Click an architecture above to hide it.
For scale: stock Linux issues NVMe commands of at most 128 KiB, because nvme-pci folds the DMA-optimal mapping size into its transfer limit. Every model on this page is far above that, so a KV block is always hundreds to thousands of commands.
IO limits are a property of the data path, not the model. The per-model numbers above were measured on the Linux kernel path; other backends carry different wire limits on identical hardware.
